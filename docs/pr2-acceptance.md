# PR2 — 공공 운동시설과 단기예보

적용 이슈는 [#1](https://github.com/heznpc/cmon-yo/issues/1)입니다. 이 문서는 handoff §8·§16의 PR2를 실제 표본과 실행 범위로 구체화합니다.

## 원본과 범위

- [전국도시공원정보표준데이터 15012890](https://www.data.go.kr/data/15012890/standard.do)의 공개 파일 다운로드를 사용합니다. `contracts/samples/muan-parks.json`은 2026-09-13 실제 수집한 무안군 관리번호 `46840-*` 21행입니다. 전국 18,202행/2페이지 수집 완료 후 지역 행을 추출했습니다. 공공시설 좌표이며 개인 위치 데이터가 아닙니다. 연락처 등 불필요한 필드는 보관하지 않습니다.
- 무안군 파일은 재현 가능한 회귀 표본이며 서비스 지역 제한이 아닙니다. 수집 지역은 `.env.example`의 `FACILITY_REGION_CODES`로 지정하고, 비우면 전국 원본을 대상으로 합니다. 적재된 지역은 Web·iOS에서 조회·선택하며 설정 변경만으로 기존 DB 행을 삭제하지 않습니다.
- 한 행은 공원입니다. identity는 `data.go.kr/15012890 + 관리번호`이며 이름/주소를 고유키로 쓰지 않습니다. 같은 이름 `남악어린이공원8`이 서로 다른 관리번호로 존재합니다.
- 운동시설은 `+`로 구분한 문자열입니다. 개별 기구 ID·수량·실시간 이용 가능 여부가 없어 이를 만들어내지 않습니다. 공원 문서의 문자열 목록을 원자적으로 교체합니다. 빈 10행은 **운동시설 정보 미제공**이며 “시설 없음”이 아닙니다. 데이터기준일 2026-07-28과 출처를 표시합니다.
- importer는 전체 페이지 개수·행 개수·지역 행을 검증한 뒤 dry-run 또는 PostgreSQL transaction/upsert를 실행합니다. 현재 제공처가 행정구역 변경 과정에서 같은 관리번호를 반복하므로 capture 단계에서 기관명이 가장 구체적인 행 하나를 결정적으로 선택하고, 저장된 snapshot의 중복 키는 여전히 거부합니다. 수집 중 총계가 바뀌면 거부합니다. 제공처의 페이지 간 동일 시점 snapshot까지 보장하지 않으며, 누락 행을 삭제/비활성화하지 않습니다.
- 날씨는 [기상청 API허브 단기예보](https://apihub.kma.go.kr/apiList.do?seqApi=10)의 `VilageFcstInfoService_2.0/getVilageFcst`와 API허브 인증키를 사용합니다. 공식 2026-06-23 가이드의 요청·응답 필드와 격자 변환을 적용했습니다. RSS 경로는 사용하지 않습니다.
- 02/05/08/11/14/17/20/23시 발표, 10분 제공 지연을 고려합니다. 공공시설 좌표를 격자로 변환해 다음 정시의 예보를 선택합니다. 발표·대상·수집 시각을 구분하고 공급자 코드를 내부 값으로 정규화합니다. 누락/미지원/결측값은 null/unknown입니다.
- 날씨 요청 deadline은 모든 페이지를 합쳐 2.5초, cache는 process-local 최대 64항목/5분입니다. 같은 격자·대상 시각의 이전 성공 응답만 갱신 실패 시 최대 1시간 보관하며, 대상 시각이 지났으면 반환하지 않습니다. cache 공유·동일 요청 결합은 보장하지 않습니다. 키 미설정/성공 이력 없음/만료는 unavailable이며 fixture fallback은 없습니다.
- Web `/places`, `/places/:id`와 SwiftUI 시설 탭을 제공합니다. API/SSR은 같은 DB service를 호출합니다. 지역은 적재된 데이터에서 선택하며 특정 군을 기본값으로 넣지 않습니다. Web·Native는 위치 권한을 요청해 허용된 기기 좌표를 지도에 표시하고, 권한 거부·타임아웃·지도 오류에서도 시설 목록과 수동 지역 선택을 유지합니다. 모임 fixture/bridge는 그대로 샘플 모임으로 접근할 수 있습니다.

인증·개인 상태·참여·GPS·시설 이용 보장·운동 적합도 정책·브랜드·XCUITest 환경 복구는 제외합니다. PR1 XCUITest(발견 2/실행 0), 실기기·VoiceOver 전체 흐름의 후속 미검증은 별개로 유지합니다.

## 수용조건

| 필수 항목 | 필요한 증거 |
| --- | --- |
| 실제 시설 표본 | 공개 원본 수집, 관리번호/행 의미/중복 이름/결측 확인, 출처와 기준일 표시 |
| ingest 정합성 | 실제 PostgreSQL dry-run 무변경, 반복·동시 적용 중복 0, 한 행 변경, 실패 rollback과 실행 기록 |
| 부분 수집 안전성 | 페이지/행 누락·malformed·중복 원본 거부. 실패로 기존 시설 삭제 안 함 |
| service·SSR | 실제 DB → HTTP API/SSR 동일 내용, 400/404/empty/DB 실패·복구, 요청별 client 정리 유지 |
| 날씨 실연결 | 인증된 공식 API 성공 응답의 실제 필드·격자·발표/대상 시각 확인. 가이드·시험 응답으로 대체하지 않음 |
| 날씨 실패 계약 | null/unknown·fresh/stale/unavailable, 부분 응답·인증 오류·timeout·취소·cache 만료 검사 |
| Web 실행 | dev/prod의 JS 없는 SSR·hydration·조회·오류/재시도, 실제 HTTP QA, 작은 화면/확대/키보드·콘솔·화면 확인 |
| Native 실행 | 앱 빌드·공통 응답 decode·실제 HTTP 통합·Simulator UI의 목록/상세·실패/복구·복귀. 각 수준 구분 |
| 경계·회귀 | lint/typecheck/test/build, DB/key browser bundle 부재, 기존 PR1 검사 영향 확인 |
| HTTP 계약 전달 | 현재 조회 3개의 OpenAPI를 실제 HTTP 응답(400/404/503 포함) 및 DB 결과와 대조. Web client의 응답 검증·취소·오류 메타데이터·404/복구와 hydration 중복 조회 없음 확인. 별도 백엔드 연동으로 과장하지 않음 |

기상청 성공 실응답 등 필수 증거가 남으면 PR2는 draft입니다. 구체적 명령·환경·관측 결과와 판정은 해당 PR의 검증 기록에 남깁니다.
