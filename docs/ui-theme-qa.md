# 동네 탐색 UI와 파란 테마 검증

2026-09-14. 첨부 색상에서 추출한 `#7893F8`을 강조색으로 사용했습니다. 동네 서비스의 정보 순서, 여백 있는 목록, 검색과 모바일 하단 탐색을 C’mon Yo의 시설·모임·커뮤니티 흐름에 적용했습니다.

## 화면 비교와 수정

| 비교 지점   | 구현과 확인 결과                                                                                                                                |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 색상        | Web `theme.ts`와 Native `NeighborhoodStyle`에 같은 강조색 적용. 강조 배경 위에는 짙은 글자색을 사용하고 링크·포커스에는 대비가 높은 파란색 사용 |
| 정보 순서   | 제목 → 설명 → 검색/조건 → 실제 데이터 목록. 시설 주소·운동시설과 모임 상태·정원을 함께 표시                                                     |
| 목록·아이콘 | 큰 카드 그림자 없이 구분선과 여백으로 행 분리. 시설·모임 아이콘과 전체 행 링크로 상세 이동                                                      |
| 글자·폭     | 제목과 보조 정보의 크기·대비 분리. 1440×1000, 390×844 및 320×740에서 200% 글자 크기 확인                                                        |
| 탐색        | Web 데스크톱 상단 탐색과 모바일 하단 4개 메뉴. 키보드 본문 바로가기 이후 검색 입력으로 포커스 이동 확인                                         |
| 작성 폼     | 제목·종목·본문·선택 정보, 미리보기·저장·폐기와 초안 보존 안내를 구분. 저장 동작을 강조색으로 표시                                               |

첫 화면의 시설·커뮤니티 제목과 설명은 시안의 문구를 유지했습니다. 작성 placeholder는 실제 제품 안내에 맞췄습니다. 시안의 예시 게시글·댓글 수·정렬 옵션과 글자 수 표시는 실제 데이터·기능으로 대체했습니다. Native는 현재 구현된 3개 탭과 시스템 컨트롤을 유지했습니다. 시안과 실행 화면의 색상·배치·문구·글자·아이콘·여백을 직접 비교했으며, 이 차이들은 제품 동작을 반영한 의도적인 차이입니다.

Native 상단 제품명이 잘리던 배치를 가운데 toolbar로 수정한 뒤 Simulator에서 재확인했습니다. Web 본문 바로가기가 탐색 메뉴를 다시 거치지 않도록 header를 main 밖에 배치하고 키보드로 검증했습니다. 목록 링크 전체 문구를 제목으로 가정하던 성능 회귀 검사는 실제 제목 heading을 읽도록 수정했습니다.

로컬 화면 실행은 `QA_PORT=3197 npm run with-env -- qa:meetings`를 사용했습니다. 시설·계정·모임용 격리 QA 데이터베이스가 필요하며 `.env.example`의 `TEST_DATABASE_URL`로 구성합니다. iOS HTTP·WebKit 검사는 별도로 `npx tsx tests/ios-server.ts`, `npm run with-env -- qa:places`도 실행합니다. 동일 포트를 사용하는 Web 회귀와 iOS 검사는 순서대로 실행합니다.

이번 코드 리뷰 범위는 변경된 Web·SwiftUI 화면, 공통 스타일, 탐색 접근성, 검색과 작성 동작에 미치는 영향입니다. 저장소 전체 코드의 리뷰 완료를 의미하지 않습니다.

## 시설 지도 누락 수정

앞선 시설 화면은 목록만 제공해 지도에서 장소를 고르는 흐름을 충족하지 못했습니다. Web에는 MapLibre GL JS와 OpenFreeMap의 실제 지도 배경을, Native에는 MapKit을 연결했습니다. 공개 시설 API의 좌표를 `#7893F8` 핀으로 표시하며 별도 지도 API 키와 사용자 현재 위치 권한은 필요하지 않습니다.

- Web 데스크톱 1440×1000에서는 지도와 시설 목록을 나란히 배치합니다. 모바일 390×844에서는 지도 → 선택한 시설 → 목록 순서입니다.
- 시설 이름·주소 검색에 따라 목록과 핀이 함께 바뀝니다. 핀 선택 → 시설 정보 카드 → 해당 시설 상세, 전체 핀 보기, 목록의 지도에서 보기를 확인했습니다.
- Codex in-app browser에서 실제 도로·지명·지도 출처 표기와 21개 시설 핀을 확인했습니다. 모바일에서 `근린공원 36`을 검색해 1개 핀으로 줄인 뒤 상세로 이동했습니다. 선택 카드의 상세 버튼이 하단 탐색에 가려지던 배치를 수정하고 재확인했습니다. 최종 새 탭에서 콘솔 경고·오류와 framework overlay는 없었습니다.
- iOS 26.3 Simulator에서 MapKit 지도와 시설 핀을 표시하고 운남공원 핀 → 시설 상세 보기 → 운남공원 상세를 확인했습니다. Simulator build는 `bash scripts/build-ios-simulator.sh /tmp/cmon-map-build`로 성공했습니다.
- 최초 지도 배경 후보의 실제 요청이 차단되는 문제를 발견해 OpenFreeMap의 공식 공개 스타일로 교체했습니다. 개발 환경의 worker 초기화 오류는 Vite worker URL을 명시해 수정했고 실제 지도 표시를 재확인했습니다.

자동 회귀 검사는 공개 지도 서버에 반복 트래픽을 보내지 않도록 시험 스타일과 GeoJSON으로 worker·핀·검색·선택·실패·재시도를 검증합니다. 외부 지도 배경 실연결 QA와 구분합니다. 지도 코드와 worker는 시설 목록이 mount된 뒤 읽으며 다른 페이지의 초기 JavaScript에 포함하지 않습니다. 이번 지도 코드 리뷰는 초기화·정리, 검색과 선택 상태 동기화, SSR 목록 유지, 키보드 핀 선택과 실패 복구를 다뤘습니다.

전체 Web 검사에서 개발 환경의 계정 전환 시험 2개가 실패했습니다. 로그아웃 후 다시 입력한 이메일이 hydration 또는 이동 중인 문서의 초기화로 사라지는 상태를 trace에서 확인했습니다. 계정 입력과 버튼은 hydration을 마친 뒤 활성화하고, 계정 전환으로 나가는 문서는 새 화면으로 이동할 때까지 잠그도록 수정했습니다. 같은 두 시험이 수정 후 통과했습니다.

날씨 재조회 중 disabled 버튼에서 키보드 포커스가 사라지는 실패도 발견했습니다. 요청 중에는 `aria-disabled`와 클릭 가드로 중복 요청을 막고 포커스를 유지합니다. 응답을 의도적으로 보류한 동안에도 포커스가 유지되는 검사를 추가했습니다.

전체 실행에서 실패한 항목은 각각 수정 후 같은 흐름으로 통과를 확인했습니다. 최종 Web 재실행은 변경 영향을 받는 시설·성능 17개를 대상으로 했습니다.

지도는 외부 연결과 WebGL에 의존하며 실패 시 목록·상세와 지도 재시도를 제공합니다. 별도의 트래픽 용량·오프라인 지도·iOS 실기기 검증은 수행하지 않았습니다.

공식 OAuth 공급자 왕복, 기상청 정상 실응답, 외부 SMTP 수신, iOS 실기기는 미검증입니다. 외부 연결 준비는 [설정 안내](integrations.md)를 따릅니다. 운영 서비스 배포와 추가 트래픽 대응은 이번 범위에 포함하지 않습니다.
